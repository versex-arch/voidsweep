## Окно программы

1. **Сканирование.** Выберите диски, решите, нужен ли *поиск мусора по всем дискам* (глубокое сканирование),
   нажмите *Начать сканирование*. Кольцо показывает, сколько найдено, а в конце делится на цветные сектора по риску.
2. **Просмотр.** Объекты сгруппированы по кодам-маркерам. Нажмите на группу, чтобы раскрыть её; на объект — чтобы
   справа увидеть, *почему его можно удалить*, размер, возраст и полный путь. *Показать в папке* открывает
   проводник; *Никогда не трогать* добавляет путь в исключения.
3. **Очистка.** Выберите *В корзину* (по умолчанию) или *Удалить навсегда*, нажмите *Очистить*, проверьте сводку и
   подтвердите. Объекты, которые изменились после сканирования, заняты программой или требуют прав
   администратора, пропускаются и показываются в отчёте.

Фильтры: поиск по имени или пути и *Все / Безопасно / Проверить / Осторожно*. *Выбрать рекомендованное*
возвращает выбор по умолчанию (всё, кроме «осторожно»).

## Команды

| Команда | Что делает |
|---|---|
| `voidsweep` | открыть окно (`--demo` — с примерными данными, `--browser` — в браузере, `--port N`) |
| `voidsweep scan` | список по группам, пять самых больших объектов в каждой |
| `voidsweep scan -v` | каждый объект с причиной |
| `voidsweep scan --deep [--drive ПУТЬ]...` | дополнительно обойти диски целиком (по умолчанию все) |
| `voidsweep scan -m КОД` | только эти маркеры (можно повторять) |
| `voidsweep scan --json` | вывод для программ, см. ниже |
| `voidsweep clean -m КОД...` | удалить объекты выбранных маркеров; сначала спросит, удаляет в корзину |
| `voidsweep clean ... --permanent` | удалить навсегда, без корзины |
| `voidsweep clean ... --dry-run` | выполнить все проверки, ничего не удаляя |
| `voidsweep clean ... -y` | не спрашивать подтверждение |
| `voidsweep markers` | описание всех кодов-маркеров |

`--lang ru|en` задаёт язык названий и причин (по умолчанию — язык системы).
Коды выхода: `0` готово, `1` отменено при подтверждении, `2` ошибка в аргументах, `3` часть объектов пропущена.

## Коды-маркеры

| Код | Риск | Выбран заранее | Что это |
|---|---|---|---|
| `TMP-01` | безопасно | да | содержимое временных папок, не менявшееся хотя бы сутки |
| `TMP-02` | проверить | да | `*.tmp` / `*.temp` старше 7 дней, блокировки Office `~$`, загрузки `.crdownload` / `.part` / `.partial`, брошенные 7 дней назад |
| `CCH-01` | безопасно | да | кэш приложений, кэш Chromium/Electron (`Cache`, `Code Cache`, `GPUCache`…), шейдерный кэш видеокарты |
| `CCH-02` | безопасно | да | кэш браузеров |
| `CCH-03` | безопасно | да | кэш миниатюр и иконок |
| `CCH-04` | проверить | да | кэш пакетных менеджеров и сборки |
| `CKE-01` | осторожно | нет | хранилища cookies — после удаления вы выйдете из аккаунтов |
| `LOG-01` | безопасно | да | логи, в которые не писали 14 дней (архивные системные логи — 7 дней) |
| `DMP-01` | безопасно | да | аварийные дампы, Windows Error Reporting, DiagnosticReports macOS, `/var/crash` |
| `UPD-01` | проверить | да | скачанные пакеты обновлений |
| `ORP-01` | осторожно | нет | папки данных уже удалённых программ, не менявшиеся 60 дней |
| `LNK-01` | безопасно | да | ярлыки `.lnk` и `.desktop`, чья цель удалена |
| `LNK-02` | проверить | да | битые символические ссылки в `~/.local/bin`, `~/bin`, на рабочем столе, в автозапуске |
| `SYS-01` | безопасно | да | `Thumbs.db`, `ehthumbs.db`, `.DS_Store`, файлы `._имя`, у которых нет `имя` |
| `DL-01` | осторожно | нет | установщики в Загрузках старше 30 дней |

Коды стабильны: новый вид мусора получает новый код, существующие коды не переименовываются и не переиспользуются.

## Где ищет

| | Windows | macOS | Linux |
|---|---|---|---|
| Временное | `%TEMP%`, `%LOCALAPPDATA%\Temp`, `%SystemRoot%\Temp` | `$TMPDIR`, `/private/tmp`, `/private/var/tmp` | `$TMPDIR`, `/tmp`, `/var/tmp` (только ваши файлы) |
| Кэш приложений | `INetCache`, `D3DSCache`, шейдеры NVIDIA/AMD/Intel, кэш Electron в `%APPDATA%` / `%LOCALAPPDATA%` | `~/Library/Caches/*` (кроме `com.apple.*`), кэш Electron в Application Support | `~/.cache/*`, кэш Electron в `~/.config` |
| Браузеры | профили в `User Data`, `cache2` Firefox | `~/Library/Caches/<браузер>`, профили в Application Support | `~/.cache/<браузер>`, профили в `~/.config` |
| Миниатюры | `Explorer\thumbcache_*.db`, `iconcache_*.db` | — | `~/.cache/thumbnails` |
| Пакеты | pip, npm, Yarn, Go, NuGet, Cargo, Bun | pip, npm, Yarn, Go, Homebrew, pnpm, Poetry, uv, Cargo | то же, что на macOS, в `~/.cache` |
| Дампы | `CrashDumps`, `WER\ReportArchive/Queue`, `Minidump`, `MEMORY.DMP` | `DiagnosticReports` | `/var/crash`, `systemd/coredump` |
| Обновления | `SoftwareDistribution\Download` | `/Library/Updates` | `*.deb` в архиве apt, `pkg` pacman |
| Ярлыки | рабочий стол, общий рабочий стол, меню «Пуск», Quick Launch, рабочий стол OneDrive | — | `~/.local/share/applications`, рабочий стол |
| Остатки | `%APPDATA%`, `%LOCALAPPDATA%` против ключей удаления в реестре, Program Files, PATH | Preferences, Saved Application State, Application Support против `.app`, Homebrew, LaunchAgents | `~/.config`, `~/.local/share`, `~/.var/app` против PATH, `.desktop`, dpkg/rpm/pacman, Flatpak, Snap |

Глубокое сканирование обходит каждый выбранный диск в поисках `SYS-01`, `TMP-02` и `DMP-01` по имени файла. Оно не
переходит в другие файловые системы и точки соединения и пропускает системные папки, `node_modules`, `.git`,
виртуальные окружения, пакеты приложений, резервные копии Time Machine и корзину.

### Как находятся остатки программ (ORP-01)

voidsweep собирает список установленного (названия, издатели, папки установки, идентификаторы пакетов, пакеты
системы, программы в `PATH`) и сравнивает с ним каждую папку данных с нестрогим совпадением. Папка попадает в список,
только если **ничего** не совпало **и** внутри ничего не менялось 60 дней. Известные системные папки всегда
пропускаются. Алгоритм скорее пропустит остаток, чем отметит живую программу, но это всё равно догадка — поэтому у
ORP-01 риск «осторожно».

## Модель безопасности

- **Страж.** Каждый кандидат дважды проходит `voidsweep.safety.Guard`: перед показом и прямо перед удалением. Он
  запрещает корни дисков, системные папки, домашнюю папку и её пользовательские папки (Рабочий стол, Документы,
  Загрузки, Изображения, Музыка, Видео, OneDrive…), сами корни временных папок и кэша и всё, что лежит не глубже
  двух уровней. Он никогда не заходит в `.ssh`, `.gnupg`, связки ключей, Keychains macOS, iCloud Drive, резервные
  копии iPhone, Почту, Сообщения, библиотеки Фото, контейнеры приложений и хранилища паролей Windows.
- **Повторная проверка.** Если время изменения объекта поменялось после сканирования, он пропускается как *изменённый*.
- **Ссылки не разыменовываются.** Символические ссылки и точки соединения удаляются как ссылки; их цели не
  трогаются, и сканер через них не проходит.
- **Владелец.** В общих папках (`/tmp`, `/var/tmp`) предлагаются только ваши файлы.
- **Возраст.** Временным файлам нужен день; забытым временным — неделя; логам — две недели; остаткам — два месяца.
- **По умолчанию — корзина.** Windows: настоящая корзина (`SHFileOperationW` с возможностью отмены). macOS:
  `~/.Trash` или Finder для других дисков. Linux: корзина freedesktop.org, так что *Восстановить* работает в любой
  графической среде.
- **Без двойного счёта.** Если выбраны и папка, и что-то внутри неё, вложенное не считается дважды и в отчёте
  помечается как удалённое вместе с родителем.
- **Исключения и журнал.** *Никогда не трогать* записывает путь в `ignore.txt`; каждая очистка пишется в
  `history.jsonl`.

## Как защищён интерфейс

Окно общается с небольшим HTTP-сервером внутри voidsweep:

- он слушает только `127.0.0.1` на случайном порту;
- каждый запрос к API требует случайный токен, который создаётся при запуске и передаётся окну во фрагменте URL
  (не уходит в сеть и стирается из адресной строки при загрузке);
- запросы, у которых `Host` или `Origin` не этот сервер, отклоняются — это защищает от DNS rebinding и
  межсайтовых запросов с открытых у вас страниц;
- статические файлы отдаются только из папки пакета, со строгой Content-Security-Policy и без встроенных скриптов;
- сервер сам останавливается, когда окно закрыто.

## JSON-вывод

`voidsweep scan --json` выводит объект с полями `findings` (список объектов) и `summary` (по кодам). Формат каждого
объекта описан в [английской версии](usage.md#json-output): `id`, `path`, `name`, `kind` (`file` / `dir` / `link`),
`size`, `files`, `mtime` (самое новое изменение внутри папки), `marker`, `risk`, `reason` (`ru` и `en`),
`needs_admin`, `covered_by` (`id` объекта, внутри которого лежит этот), `preselect`.

## Какие файлы хранит voidsweep

| ОС | Папка |
|---|---|
| Windows | `%LOCALAPPDATA%\Voidsweep` |
| macOS | `~/Library/Application Support/Voidsweep` |
| Linux | `~/.config/voidsweep` |

`settings.json` (язык), `ignore.txt` (исключения, по одному пути на строку), `history.jsonl` (последние 100 очисток)
и `window-profile` (отдельный профиль браузера для окна программы). Переменная `VOIDSWEEP_HOME` задаёт другую папку.
Свою папку voidsweep никогда не предлагает удалить.

## Как добавить правило

Правила лежат в `voidsweep/rules.py`. Правило — это генератор кандидатов:

```python
def my_rule(env):
    yield from single(env.home / ".myapp" / "cache", "CCH-01", "app_cache", {"app": "MyApp"})
```

Добавьте его в `build_rules()` (более точные правила — раньше: путь достаётся первому правилу), напишите тест в
`tests/` и откройте pull request. Для нового вида мусора нужен новый маркер в `voidsweep/markers.py` с названием,
описанием и текстом причины на обоих языках.

## Ограничения

- Готовые сборки не подписаны, поэтому SmartScreen и Gatekeeper предупреждают при первом запуске.
- Некоторые объекты требуют прав администратора (системная Temp, Windows Update, `/var/crash`). Без них они
  показываются со значком и пропускаются при очистке; voidsweep сам права не запрашивает.
- Файлы, открытые другой программой (кэш запущенного браузера, базы миниатюр), могут быть пропущены как *занятые*.
- Защита приватности macOS (TCC) скрывает некоторые папки, если у программы нет полного доступа к диску.
- Поиск остатков программ — эвристика, см. выше.
